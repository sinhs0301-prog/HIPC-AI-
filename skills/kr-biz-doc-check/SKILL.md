# 한국 사업 문서 점검 지침 (kr-biz-doc-check)

idea_key: kr-biz-doc-check-skill

## 언제 이 지침을 쓰는가

아래 중 하나라도 해당하면 적용한다.

- 사용자가 견적서/계약서/세금계산서 초안의 **사업자등록번호**를 넣거나 확인해 달라고 할 때
- CSV·TXT·MD 파일을 열었더니 한글이 `ì•ˆë…•` 처럼 보일 때
- 금액에 **부가가치세**를 붙이거나 역산해야 할 때

적용하지 않는 경우: 세무 신고 대행, 전자세금계산서 실제 발행, 법인등기·휴폐업 조회(이 지침에는 외부 조회 기능이 없다).

## 작업 순서 (먼저 할 일부터)

1. **인코딩 먼저 확인한다.** 글자가 깨진 상태로 번호나 금액을 읽으면 이후 검증이 전부 무의미하다. 파일 내용에 `ì`, `â€`, `ë` 같은 조각이 보이면 1단계로 복구한다.
2. **사업자등록번호 체크섬을 검증한다.** 형식(10자리)만 맞는 번호는 매우 흔한 오타를 통과시킨다.
3. **금액·부가세를 자가검산한다.** 소계 → 세액 → 합계 순서로 세 수치를 따로 계산해 대조한다.
4. 위 3단계에서 하나라도 불일치하면, 보정한 값을 사용자에게 **추정이 아니라 후보로 제시**하고 원문 확인을 요청한다.

## 1단계: 깨진 한글 판별

판별 규칙(에이전트가 직접 적용 가능):

- UTF-8 바이트를 cp1252/latin-1로 잘못 읽은 경우가 대부분이다. 증상 문자열: `ì`, `í`, `ë`, `â€œ`, `Ã`, `ï»¿`(BOM).
- 완성형(EUC-KR)을 UTF-8로 읽은 경우는 `\ufffd`(�)가 연속으로 나타난다. 이 경우 **원본 바이트가 이미 손실됐을 수 있어 복구가 불가능**하다. 화면에 표시된 문자열만으로 되돌리려 하지 말고 원본 파일을 다시 받아야 한다.
- 복구 시도는 항상 **원본을 보존한 채 사본**에 하고, 복구 결과에 한글 음절(가–힣) 비율이 늘었는지로 성공을 판정한다. 비율이 줄면 잘못된 추정이므로 되돌린다.

## 2단계: 사업자등록번호 검증 (체크섬)

국세청 10자리 번호의 마지막 자리는 검증 숫자다.

```
가중치 = [1, 3, 7, 1, 3, 7, 1, 3, 5]
합 = Σ(앞 9자리[i] × 가중치[i])
합 += (9번째 자리 × 5) // 10        # 9번째 자리에만 추가 보정
검증숫자 = (10 - (합 % 10)) % 10
```

검증숫자가 10번째 자리와 같아야 유효하다.

입력 정규화 규칙:

- `123-45-67890`, `123 45 67890`, `12345 67890` → 하이픈·공백·전각문자를 제거하고 숫자 10자리만 남긴다.
- 숫자가 10자리가 아니면 **검증 실패가 아니라 형식 오류**로 구분해 보고한다. (9자리·11자리는 자릿수 누락/중복 입력일 가능성이 높다.)
- `0000000000` 같은 반복 숫자는 체크섬을 우연히 통과할 수 있으므로 별도 경고한다.

### 입력 검증 예시

| 입력 | 정규화 | 판정 | 에이전트가 할 말 |
|---|---|---|---|
| `220-81-62517` | 2208162517 | 체크섬 통과 | "형식·체크섬은 유효합니다. 실제 사업자 존재 여부는 국세청 홈택스에서 별도 조회가 필요합니다." |
| `220-81-62518` | 2208162518 | 체크섬 불일치 | "마지막 자리가 맞지 않습니다. 원본 서류를 다시 확인해 주세요." |
| `220-81-6251` | 9자리 | 형식 오류 | "숫자가 9자리입니다. 한 자리가 빠졌는지 확인해 주세요." |
| `ì‚¬ì—…ìž 220-81-62517` | 깨진 텍스트 포함 | 1단계로 회귀 | "파일 인코딩이 깨져 있습니다. 번호 외 항목도 손상됐을 수 있습니다." |

**중요:** 체크섬 통과는 그 번호가 실제 존재하거나 영업 중이라는 뜻이 아니다. 이 지침은 오타 탐지용이며, 실존·휴폐업 여부는 홈택스 조회가 필요하다고 반드시 함께 안내한다.

## 3단계: 부가세 자가검산

일반 과세 기준 10%.

```
부가세 = round(소계 × 0.10)      # 원 단위 반올림
합계   = 소계 + 부가세
```

자주 나오는 실패 사례:

- **역산 오류:** 합계에서 공급가액을 구할 때 `합계 ÷ 1.1`이며, `합계 × 0.9`가 아니다. 110,000원 → 100,000원(O), 99,000원(X).
- **반올림 위치:** 품목별로 반올림한 뒤 더한 값과 소계에 한 번 반올림한 값이 1~2원 다를 수 있다. 문서에는 어느 방식인지 명시한다.
- **세율 오적용:** 면세 품목(일부 도서·농수산물 등)이나 영세율 거래에 10%를 붙이면 안 된다. 과세 여부가 불확실하면 금액을 확정하지 말고 사용자에게 묻는다.

## 한계와 책임 범위

- 외부 조회(국세청·전자세금계산서) 기능이 없다. 계산과 형식 검증만 한다.
- 세무·법률 자문이 아니다. 실제 신고 금액은 세무 담당자 확인이 필요하다.
- 되돌릴 수 없게 깨진 파일은 복구하지 못한다.

## 참고 구현

이 지침의 체크섬·복구 판정 로직을 실행 코드로 확인하려면 같은 패키지의 `scripts/` 파일을 사용한다. 코드 없이 지침만으로도 에이전트가 위 규칙을 직접 적용할 수 있다.
