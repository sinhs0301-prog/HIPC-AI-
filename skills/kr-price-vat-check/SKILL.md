# 한국 가격·부가세 표기 점검 스킬 (v2.1)

## 언제 쓰나
- 견적서/계약서/완료보고서에 `소계 · 부가세 · 합계`를 적었는데 수치가 맞는지 확인할 때
- 상세페이지에 "부가세 별도"를 쓸지, 총액(VAT 포함)으로 표기할지 판단할 때

## 버전 이력
- v1: 지침만 있었고 실행 코드가 없었다.
- v2: 실행 가능한 점검 스크립트 `vat_check.py` 를 포함했다(자체 검사 7건 통과, run_id `9bfe5d6adc1449408cb2de01c8f06057`, exit 0).
- **v2.1: 역산(포함가 → 공급가/세액) 안내를 이 스킬에서 제거했다.** 이유: 실제 실행 검사(run_id `fbee4fbc551247549cc9478f00b8b210`)에서 `공급가 = round(합계/1.1)` 규칙을 1~200,000원 전 구간에 적용하면 18,182건(9.091%)에서 `공급가 + round(공급가*0.1) ≠ 합계` 가 되어 재구성이 깨졌다(예: 합계 5, 16, 27 … 및 1,000원 단위 6,000·17,000·28,000·39,000·50,000·61,000·72,000·83,000). 또한 `vat_check.py` 에는 역산 전용 함수가 없어 문서와 구현이 불일치했다. 따라서 역산은 삭제하고, 이 스킬은 **검증(check) 전용**으로 범위를 좁혔다.

## 계산 규칙 (이 스킬이 강제하는 기준)
1. 일반과세 세율은 **10%** 다. 5%·7% 같은 임의 세율을 쓰지 않는다.
2. 별도 표기일 때: `부가세 = round(소계 * 0.10)`, `합계 = 소계 + 부가세`.
3. 면세/영세율 표기(`면세`, `영세율`)가 보이면 10% 판정을 **보류(SKIP)** 하고 사람에게 확인을 요청한다.
4. 금액이 1개뿐이면 교차검증이 불가능하므로 `INSUFFICIENT` 로 보고하고 추정하지 않는다.
5. 합계만 적힌 포함가 문서는 이 스킬의 범위 밖이다. 공급가·세액을 추정해 적지 말고 원 자료(소계)를 확인한다.

## 표기 점검 체크리스트
- [ ] 소비자 대상 최종 가격이 **VAT 포함 총액**으로 보이는가 (부가가치세법상 총액표시 대상 여부를 사업자가 확인)
- [ ] "부가세 별도"를 썼다면 실제 청구 합계도 별도 기준으로 계산되어 있는가
- [ ] 설명문("부가세 10%")과 예시 금액(실제로는 5%)이 어긋나지 않는가 — 가장 흔한 실수
- [ ] 할인 적용 순서: 할인 후 공급가에 세율을 적용했는가
- [ ] 원 단위 절사를 했다면 합계 = 소계 + 부가세 항등식이 여전히 성립하는가

## 사용법
```
python3 vat_check.py --self-test          # 내장 검사 7건 실행
python3 vat_check.py --file quote.txt     # 문서에서 금액을 찾아 점검
python3 vat_check.py --text "소계 65,000원 부가세 6,500원 합계 71,500원"
```
판정값: `ok` / `mismatch` / `skip` / `insufficient`.

실입력 교차검증 근거(run_id `d56b3b00`, 팀 검토 t25 승인): 정상 케이스(65,000 / 6,500 / 71,500)는 exit 0·RESULT ok, 5% 오표기 케이스(65,000 / 3,250 / 68,250)는 exit 1·MISMATCH 2건 탐지.

## 한계 (과장하지 않음)
- 세무 자문이 아니다. 간이과세·면세사업자·수출 영세율·의제매입세액은 다루지 않는다.
- **포함가 역산 기능은 제공하지 않는다**(v2.1에서 제거). 반올림 경계 때문에 정확히 되돌릴 수 없는 금액이 약 9% 존재한다.
- 한국어 표기(`소계/공급가/부가세/합계/총액`) 기준의 정규식 추출이므로, 표 이미지나 PDF는 읽지 못한다.
- "총액표시제 위반"을 법적으로 단정하지 않고 **확인이 필요한 항목**으로만 표시한다.
- 실제 판매 실적이나 수익을 보장하지 않는다.
