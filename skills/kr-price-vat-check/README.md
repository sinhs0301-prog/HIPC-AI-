# kr-price-vat-check (v2.1)

idea_key: kr price vat check skill v2

한국 부가가치세(10%) 표기가 섞인 가격 문구를 점검하는 에이전트용 스킬 + 실행 가능한 검사 스크립트.

## v2.1에서 바뀐 점 (중요)

v2 문서에 있던 "역산: 순액 = round(총액 / 1.1)" 안내를 **삭제했다.**

이유(실측):

- 내가 작성한 검사 `agents/claude_lab1/vat_rounding_edge.py`를 1원~200,000원 전 구간에 적용한 결과,
  `net = round(T/1.1)` → `vat = round(net*0.1)` → `net+vat` 가 원래 총액 T와 **일치하지 않는 경우가 18,182건(9.091%)** 나왔다.
  (예: T=5, 16, 27, 38, 49, 60, 71, 82 … 및 1,000원 단위에서도 6,000 / 17,000 / 28,000 / 39,000 / 50,000 / 61,000 / 72,000 / 83,000 등)
- 또한 `vat_check.py`에는 역산 전용 함수가 존재하지 않는다. 즉 문서가 안내하던 경로를 코드가 제공하지 않는 **문서-구현 불일치**였다.

따라서 이 스킬은 **검증(check) 기능만** 제공한다. 총액에서 공급가액을 되돌리는 계산은 이 스킬의 범위가 아니다.

## 하는 일

문장/표에 적힌 `공급가액 / 부가세 / 합계` 숫자를 읽어,

1. 부가세가 공급가액의 10%(원 단위 반올림)와 일치하는지
2. 합계가 공급가액 + 부가세와 일치하는지

를 검사하고 불일치를 지적한다. 실무에서 흔한 **부가세율 오표기(예: 5%)**, **합계 오타**를 잡는 용도다.

## 사용법

```bash
# 내장 자체검사
python3 vat_check.py --self-test

# 실제 문구 검사
python3 vat_check.py --text "공급가액 65,000원 부가세 6,500원 합계 71,500원"
```

종료 코드: 문제 없음 `0`, 불일치 발견 `1`.

검증된 동작 예:

- `공급가액 65,000 / 부가세 6,500 / 합계 71,500` → exit 0, RESULT ok
- `공급가액 65,000 / 부가세 3,250 / 합계 68,250` (5% 오표기) → exit 1, MISMATCH 2건

## 한계 (반드시 읽을 것)

- 세무·법률 자문이 아니다. 최종 신고 금액은 세무 담당자/국세청 기준을 따르라.
- 면세·영세율·간이과세·수입 부가세 등 10% 이외 상황은 다루지 않는다.
- 원 단위 반올림 규칙은 거래처·시스템마다 다를 수 있다(절사/절상). 이 스킬은 `round` 기준 한 가지만 본다.
- PDF/엑셀 파싱 기능은 없다. 텍스트로 붙여넣어야 한다.
- 총액 → 공급가액 역산은 제공하지 않는다(위 v2.1 설명 참고).
