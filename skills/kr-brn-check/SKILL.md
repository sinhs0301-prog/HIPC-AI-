# 한국 사업자등록번호 오류 검증 (kr-brn-check)

## 언제 쓰나
에이전트가 다음 작업을 할 때 **입력값을 먼저 검증**하는 용도다.

- 거래처 대장/엑셀에 받아적은 사업자등록번호를 정리할 때
- 세금계산서·견적서·계약서 문서를 생성하기 전에
- 고객이 채팅/메일로 보낸 번호를 받아 기록할 때

오타가 섞인 번호로 세금계산서를 발행하면 재발행·수정발행 사유가 되고, 거래처 대장이
오염되면 나중에 어느 줄이 틀렸는지 찾기 어렵다. 이 스킬은 **외부 조회 없이 오프라인에서**
단일 자리 오타 대부분을 즉시 걸러낸다.

## 검증 규칙 (공개된 공식 체크섬)
번호를 숫자 9자리(d1..d9)와 검증자리(d10)로 나눈다.

1. 가중치 `W = [1, 3, 7, 1, 3, 7, 1, 3, 5]` 를 d1..d9에 각각 곱해 더한다.
2. 여기에 `(d9 * 5) // 10` 을 추가로 더한다.
3. `(10 - (합계 % 10)) % 10` 이 d10과 같아야 유효하다.

동치 표현으로, 위 합계에 d10을 더한 값이 10의 배수여야 한다.

## 사용법

```bash
python brn_check.py 123-45-67890
python brn_check.py 1234567890 2208162517
python brn_check.py --file 거래처목록.txt
python brn_check.py --help
```

출력 예시(형식):

```
1234567890  INVALID  checksum mismatch (expected last digit 8)
2208162517  VALID
```

종료 코드: 모두 유효하면 0, 하나라도 무효면 1. 파이프라인에서 게이트로 쓸 수 있다.

## 에이전트가 따라야 할 절차

1. 사용자가 사업자등록번호를 제시하면 **먼저 이 검사기를 돌린다.**
2. INVALID가 나오면 문서를 생성하지 말고, 사용자에게 원본을 다시 확인하도록 요청한다.
   이때 "틀렸다"가 아니라 "체크섬이 맞지 않아 오타 가능성이 있다"로 안내한다.
3. VALID가 나와도 **실제 존재하는 사업자라는 뜻은 아니다.** 실재 여부·휴폐업 상태는
   국세청 홈택스 사업자상태 조회에서 별도로 확인해야 한다고 반드시 덧붙인다.

## 한계 (반드시 함께 안내할 것)

- 체크섬 검사만 한다. 존재 여부, 휴업·폐업, 상호/대표자 일치는 확인하지 못한다.
- 두 자리 이상이 동시에 바뀐 오타나 자리바꿈 일부는 우연히 통과할 수 있다.
  (단일 자리 오타는 구조상 전부 검출된다.)
- 10자리 숫자가 아니면 검증 대상이 아니라 형식 오류로 처리한다.
- 법인등록번호(13자리), 주민등록번호와는 규칙이 다르므로 이 스킬로 검사하지 않는다.
